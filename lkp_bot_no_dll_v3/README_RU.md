# Локальный помощник по реставрации ЛКП

Бот ищет технические обсуждения в вашей SQLite-базе. Локальная Ollama объясняет найденные сведения своими словами и проверяет смысл ответа по исходным сообщениям. Бот хранит факты текущего случая, чтобы учитывать уточнения. Это поиск с генерацией ответа, а не обучение модели на переписке. Архив не передаётся внешнему ИИ в режиме по умолчанию. Интернет нужен для самого Telegram и первоначального скачивания программ/моделей.

## Обновление существующего бота в Windows

1. Закрой окно работающего бота. Сохрани копию его папки целиком в отдельное место. Дополнительно можно скопировать туда `backup_project.py` и `backup_windows.bat` из обновления и запустить `backup_windows.bat`: он создаёт проверенную копию в соседней папке `lkp_bot_no_dll_v3_backups`. В ней могут быть секреты — не загружай её в GitHub.
2. Скопируй файлы обновления поверх файлов программы. **Сохрани свои `.env`, `knowledge.sqlite` и `access.sqlite`: не удаляй и не подменяй их.** Пакет обновления не содержит этих файлов. Старый `bot_backup.py` — историческая версия; запускается именно `bot.py`.
3. В своём `.env` проверь `AI_PROVIDER=ollama` и `AI_MODEL=` с точным именем уже установленной модели. Посмотреть имена можно командой `ollama list`. Оставь `ALLOW_EXTERNAL_AI=false`. Обновление не переписывает `.env`.
4. Запусти Ollama, затем `start_python312.bat`. Нужен установленный Python 3.12; BAT создаёт отдельное окружение и устанавливает прежние три зависимости. Новых библиотек с нативными DLL не добавлено.
5. Напиши боту `/start`, задай вопрос, затем уточнение. `/new` или `/reset` начинает новую тему. После получаса бездействия история перестаёт использоваться.
6. Запусти `check_dialogue_windows.bat`, когда бот свободен: он проверит несколько сообщений подряд, включая пример с ИК-сушкой по 2 минуты. Ответы появятся в окне и в читаемом TXT-отчёте в `evaluation/results/`. `compare_windows.bat` отдельно сравнивает исходный и новый алгоритмы на одиночных вопросах. Оба запуска работают локально.

Для отката останови бота и верни программные файлы из своей резервной копии. Текущие `.env` и обе базы оставь на месте, чтобы не откатить недавно выданные доступы и статистику. Если нужна полная аварийная копия данных — она есть в резервной папке; её восстановление вернёт данные на момент копирования.

## Первая установка

Установи Python 3.12 и Ollama для Windows. Распакуй папку полностью. Запусти `setup_windows.bat`: он создаст `.env` из включённого `.env.example`, не меняя уже существующий файл. Впиши Telegram-токен и свой числовой Telegram ID. Токен не присылай в переписку.

Нужны `knowledge.sqlite` с архивом и установленная модель Ollama. Если модель уже работает, оставь её точное имя. `start_python312.bat` запускает бота. `access.sqlite` хранит доступы и дневные лимиты; существующий файл всегда сохраняй.

Пример локальных настроек без секретов:

```ini
AI_PROVIDER=ollama
AI_MODEL=qwen3:4b-instruct
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_NUM_CTX=8192
OLLAMA_NUM_PREDICT=1200
SEMANTIC_SEARCH=false
ALLOW_EXTERNAL_AI=false
```

`qwen3:4b-instruct` здесь — имя из существующей установки владельца. Если `ollama pull` не узнаёт такой тег, сначала проверь `ollama list` и укажи фактическое имя модели, не меняя его наугад.

Команды ниже выполняй в PowerShell из папки бота. После подготовки окружения:

```powershell
.\.venv312\Scripts\python.exe doctor.py
.\.venv312\Scripts\python.exe -m unittest discover -s tests -v
.\.venv312\Scripts\python.exe evaluate.py
```

`doctor.py` проверяет наличие настроек, базу и доступность Ollama. Он не печатает секреты и не отправляет сообщения ученикам. Тесты проверяют код; качество настоящих ответов проверяется отдельно через `evaluate.py --generate`.

## Как устроен улучшенный поиск

Поиск читает имеющуюся базу без её изменения. Он учитывает варианты технических слов, включая «катер/каттер», «подрезка/срезание», «выдирает/вырывает» и короткое «ИК». Сначала собирает кандидатов по всему индексу, затем оценивает сочетание понятий и близость совпадений. Одного случайного общего слова недостаточно.

В контекст передаются полезные сообщения с соседними репликами. Перекрывающиеся сообщения не повторяются; номера и заголовки источников не передаются модели. Длинные сообщения выбираются по релевантным предложениям, а не всегда отрезаются с начала. При этом ошибка или обрывок в старом архиве не становятся достоверным фактом автоматически.

## Ответ своими словами и понимание уточнений: dialogue-synthesis-v3

Предыдущий режим с выбором цитат оказался слишком жёстким: он повторял одинаковые выдержки и задавал общий вопрос, даже когда ученик уже ответил. Он заменён пересказом с проверкой по источникам.

1. Бот сохраняет тему и факты, которые сообщил ученик: кисть или аэрограф, способ сушки, длительность одного цикла, количество циклов, температуру, состояние и название материала. Исправление заменяет прежний факт. «По 2 минуты» не считается общим временем сушки.
2. Поиск учитывает тему и последнее уточнение. После сообщения про ИК-сушку повышается приоритет подходящих обсуждений с ИК. Номера сообщений используются внутри программы для проверки происхождения, в ответ ученику не попадают.
3. Модель пишет связный ответ своими словами: объяснение, возможные причины и проверки, которые подтверждены найденными сообщениями. Для каждого смыслового пункта она указывает программе исходные реплики. Длинное дословное копирование отправляется на переформулировку.
4. Программа проверяет ссылки на реальные реплики, числа, названия компонентов и факты ученика. Нельзя соединить признак растворителя с названием другого компонента. Неизвестному составу не назначаются произвольные добавки и числовые режимы.
5. Второй запрос к той же локальной модели проверяет смысл: сохраняются ли условия, не придумана ли причинная связь, подходит ли совет к способу нанесения и последнему уточнению. Такая проверка может ошибиться; она не гарантирует техническую истинность.
6. При отклонении есть одна попытка исправления. Если подтверждений всё ещё недостаточно, бот уточняет действительно недостающий факт. Уже известный или ранее заданный вопрос из списка уточнений не повторяется.

В примере «долго сохнет» → «сушу лампой ИК по 2 минуты» второй запрос получает тему, факт нанесения кистью, ИК-лампу и длительность одного цикла. Он не может снова выбрать вопрос «Как сушишь?». При этом бот не должен объявлять две минуты недостаточными без подходящих подтверждений для материала.

Предыдущие технические ответы ИИ не передаются в запросы как знания. Для связи с прошлым ответом передаются только идентификаторы уже использованных исходных реплик. Полные прошлые ответы хранятся локально в оперативной памяти для проверки повторов, распознавания ответа на уточнение и исправления неподтверждённых названий. Четыре последних хода ограничены по объёму; факты текущего случая сохраняются отдельно. Через 30 минут бездействия, по `/new` или `/reset` история и факты очищаются. После перезапуска бота они также не сохраняются.

После обновления в консоли или `doctor.py` должна быть версия `dialogue-synthesis-v3`. Переиндексация базы не нужна. Свою работающую модель можно оставить. Лимит генерации теперь не меньше 1000 токенов, даже если в старом `.env` осталось 650: короткого лимита не хватало для законченного JSON с объяснениями. По умолчанию используется 1200.

Администратор может отправить `/evidence` **в личном чате**: бот покажет смысловые пункты последнего ответа и исходные реплики, на которые они опирались. В группе и для учеников эта команда недоступна.

Обычный ответ требует двух обращений к локальной модели; с исправлением — до четырёх. Настоящая генерация в облаке не проверена: нет Ollama, а загрузка модели ограничена сетью. Здесь проверены поиск по реальной базе, состояние диалога и ограничения программы; ответы модели в автотестах имитируются.

Для реальной проверки запусти `check_dialogue_windows.bat`. Он воспроизводит цепочку из трёх сообщений про сушку и отдельный диалог про каттер. JSON-отчёт содержит основания и статусы, TXT — вопросы и ответы для чтения. Файлы остаются на компьютере. Если вместо объяснения получается уточнение, это видно в статусе; положительные автопризнаки не заменяют оценку мастера.

## Модели для RTX 3060 Ti 8 ГБ

Сначала проверь новую логику на своей текущей Qwen3 4B. Она экономна по памяти, но небольшой модели трудно одновременно разбирать противоречивую переписку и аккуратно объяснять технические нюансы.

Первый кандидат для сравнения — **Qwen2.5 7B Instruct Q4_K_M**: локальная, без обязательного режима рассуждений, с поддержкой русского языка. Второй — **Qwen3 8B Q4_K_M** с отключёнными рассуждениями. Обе модели крупнее 4B, но прирост именно на твоих вопросах нужно измерить, а не обещать заранее.

```powershell
ollama pull qwen2.5:7b-instruct-q4_K_M
.\.venv312\Scripts\python.exe evaluate.py --generate --candidate-model qwen2.5:7b-instruct-q4_K_M
```

Или:

```powershell
ollama pull qwen3:8b-q4_K_M
.\.venv312\Scripts\python.exe evaluate.py --generate --candidate-model qwen3:8b-q4_K_M
```

Первая команда `evaluate.py --generate` без кандидата сравнивает старый и новый алгоритм на одной модели. Команды с кандидатом меняют одновременно алгоритм и модель; чтобы оценить отдельно влияние модели, сравни также два результата нового алгоритма. Генерация фиксирует seed, но это не гарантирует одинаковых ответов на разных версиях Ollama/оборудовании. Семантический индекс в этом сравнении не включается.

У квантованных 7–8B только веса занимают примерно 4,7–5,2 ГБ; дополнительно нужны память контекста, вычислений и Windows. Начни с контекста 8192 и одного запроса к модели одновременно. Смотри `ollama ps`: частичная выгрузка на CPU замедлит ответы. Если памяти не хватает, закрой другие GPU-программы, затем попробуй `OLLAMA_NUM_CTX=4096`; бот уменьшит объём заметок и истории, и полнота ответа может снизиться. Если это мешает, вернись к 4B с окном 8192. Модели 14B и больше не рекомендованы как основной быстрый вариант для 8 ГБ VRAM. Скорость на этом компьютере здесь не измерялась.

Страницы моделей: https://ollama.com/library/qwen2.5 и https://ollama.com/library/qwen3. Модельные файлы скачиваются при `pull`; вопросы и архив при этом не передаются.

## Необязательный смысловой поиск

Текстовый поиск уже работает без дополнительных моделей. Для поиска похожих формулировок по смыслу добавлен **опциональный** локальный индекс через `bge-m3`. Он требует отдельной первоначальной индексации. На реальной embedding-модели этот режим в облаке не проверен: сначала сравни его на своих вопросах.

```powershell
ollama pull bge-m3
.\.venv312\Scripts\python.exe semantic_search.py
```

Когда появится `embeddings.sqlite`, поставь в `.env`:

```ini
SEMANTIC_SEARCH=true
EMBEDDING_MODEL=bge-m3
```

Модель векторов работает на CPU, чтобы оставить видеопамять основному ИИ. Данные отправляются только локальной Ollama. Векторный индекс хранится отдельно; проверяются хеш базы, digest модели и размерность. Незавершённая индексация продолжается из `.partial`. Для обновления готового индекса используй `semantic_search.py --replace`: старая версия сохраняется в `.bak`. Если индекс отсутствует, устарел или Ollama не отвечает, бот использует текстовый поиск. Векторные кандидаты также проходят проверку совпадения технических понятий; это намеренно осторожный гибрид, поэтому он не найдёт все чисто смысловые совпадения.

## Полный архив Telegram

В переданной базе представлены 33 868 уникальных номеров сообщений, а полного экспорта на примерно 44 000 сообщений в репозитории нет. Нельзя восстановить отсутствующие сообщения или обрезанные окончания из этой базы.

Когда у тебя будет экспорт чата из Telegram Desktop в JSON, создай **отдельную** новую базу, оставив старую:

```powershell
.\.venv312\Scripts\python.exe build_index.py --source "D:\Архив\result.json" --output knowledge_full.sqlite --format telegram
```

Или из прежнего формата JSONL:

```powershell
.\.venv312\Scripts\python.exe build_index.py --source lkp_candidate_discussions.jsonl --output knowledge_full.sqlite --format jsonl
```

Новый индексатор сохраняет длинные сообщения целиком, читает форматированные Telegram-тексты и подхватывает родительские сообщения ответов через паузы в разговоре. Не распознаёт фото, голосовые и видео. Он не редактирует исходный JSON. Существующий файл назначения не заменяется без `--replace`; при замене сначала проверяется новая база и сохраняется резервная копия старой.

Проверь новую базу и поиск прежде, чем использовать её вместо `knowledge.sqlite`. Останови бота, сохрани старый файл отдельно, подставь новый под именем `knowledge.sqlite`, затем при необходимости перестрой embedding-индекс. Старые эталонные номера фрагментов из проверки неприменимы к новой базе: программа отключит соответствующую метрику, потребуется новая разметка.

## Доступы, ограничения и приватность

Сохранены `/grant ID 180`, `/revoke ID`, `/stats`, `/status`, `/id`, дневные лимиты и администраторы. Ошибка модели или отсутствие одобренного объяснения возвращают потраченный дневной запрос. Генерация выполняется по одному запросу, чтобы несколько учеников не переполнили видеопамять.

Режим `offline` показывает непроверенные выдержки без генерации и без номеров источников; это не готовый технический ответ. Совместимость с ProxyAPI оставлена, но запуск требует `ALLOW_EXTERNAL_AI=true` и ключа. Для твоей задачи оставляй `false` и `AI_PROVIDER=ollama`.

`.env`, результаты генерации и векторные индексы исключены из Git. Существующие `knowledge.sqlite` и `access.sqlite` уже отслеживаются в этом репозитории; обновление не удаляет их и не меняет историю Git. Не добавляй туда новые личные данные или токены. Не публикуй резервные копии.

Самый полезный следующий шаг — проверенные преподавателем ответы и технологические карты конкретных составов. В архиве есть противоречия, а роли авторов в текущей базе не сохранены; бот не может надёжно определить, кто из участников прав.
